
- Do not open and re-save these files in Excel. It can turn Bengali into garbled characters or `?`.

## What you need to produce

Three outputs, all generated by your code.

### 1. NER → `predictions/ner_predictions.csv`

Run your NER model on **every** test note. One row per predicted entity:

```
note_id,start,end,entity_type
MB-XXXX,6,10,SYMPTOM
```

- `start` and `end` are character offsets into `note_text`. Count **Unicode code points**,
  start at 0, and treat `end` as **exclusive**.
- Bengali conjuncts use several code points. Example: in `রোগীর জ্বর আছে।`, the word `জ্বর`
  is 4 code points (জ + ্ + ব + র), so it has `start=6`, `end=10`. Zero-width joiners and
  non-joiners also count as code points.
- `entity_type` must be one of the schema types: `DIAGNOSIS`, `SYMPTOM`, `MEDICATION`,
  `DOSAGE`, `TEST`, `TEST_RESULT`, `BODY_SITE`, `PROCEDURE`, `TEMPORAL`,
  `NEGATION_UNCERTAINTY`.
- You may add an `entity_text` column to check your offsets (`text[start:end] == entity_text`).
  It is ignored in scoring.

### 2. Clustering and analysis → `predictions/clusters.csv` and `predictions/analysis/`

Assign **every** test note to exactly one cluster, using features from your NER output:

```
note_id,cluster_id
MB-XXXX,3
```

- You choose the number of clusters. Do not use any phenotype labels. None are provided.
- Put your frequency analysis and relationship analysis of the extracted entities
  (tables or charts) in `predictions/analysis/`.
- Report your own Silhouette and Davies-Bouldin scores in your technical report.

### 3. Question answering (RAG) → `predictions/rag_outputs.jsonl`

Run **every** query twice:

- corpus `"test"`: retrieve only from the test notes in `round2_release/`
- corpus `"own"`: retrieve only from your own annotated corpus

Write one JSON object per line, per query and corpus (two lines per query):

```json
{"query_id": "q04", "corpus": "test", "retrieved_note_ids": ["MB-XXXX", "MB-XXXX"], "retrieved_passages": ["..."], "answer": "..."}
```

- `retrieved_note_ids`: up to 20 note IDs, best match first. For corpus `"own"`, use the
  `note_id` values of your own corpus.
- Write the `answer` in Bengali (medical terms may stay in English), using only the
  retrieved passages.
- No external APIs and no web retrieval.
- If you use fine-tuning instead of retrieval, leave `retrieved_note_ids` and
  `retrieved_passages` empty and explain your approach in your report.

## What a good answer looks like

| If the query asks you to… | A good answer… |
|---|---|
| Find or show patients | Lists the matching patients (note IDs), with a one-line summary each |
| List medications or findings | Gives a de-duplicated list, with counts if you can |
| Describe a group of patients | Summarizes the typical symptoms, tests and treatment |
| Match very many notes | Gives the total count, a few examples and a summary. You do not need to list everyone |
| Include a condition such as a negation or a number | Respects it exactly (for example, "told antibiotics are not needed", or a value above a limit) |
| Match nothing in the corpus | Says clearly that no matching notes were found |

**Do not invent patients.** For some queries in some corpora, "no matching notes found" is the
correct answer, and it scores better than a made-up one.

## Rules for the test data

- Do not label, edit or redistribute the test notes by hand. Your predictions must come from your pipeline.
- Your code must reproduce your submitted results exactly. Set random seeds and include `requirements.txt`.

## How it will be scored

- **NER:** entity-level precision, recall and F1 by exact span match, overall and by entity type.
- **Clustering:** agreement with hidden phenotype labels (NMI and Adjusted Rand Index), plus your own
  Silhouette and Davies-Bouldin scores and a review of cluster quality.
- **RAG:** retrieval checked against reference note IDs for the test corpus, plus a clinical advisor's
  rubric (retrieval relevance, groundedness, correctness). For queries with many matches, we mainly
  check the top of your ranked list.
- **Reproducibility:** a sample of notebooks will be re-run and compared with the submitted files.
